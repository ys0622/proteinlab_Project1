# 제품 소개 글 쓰기 (ProteinLab, 2026-11-08) — 에이전트용

저장소 D:\proteinlab. 맡은 slug 목록 파일(아래 SLICE)에 있는 제품마다 소개 글을 쓴다. 결과는 OUT 파일 하나에 `{ "<slug>": {summary, points, goodFor, watchOut, compareSlugs, sources} }` JSON으로 쓴다. 다른 파일은 고치지 않는다(app/ 아래 수정 금지, git 작업 금지).

## 기준 예시
`app/data/productEditorial.json`의 기존 60개가 기준이다. 먼저 `takefit-max-goso-250`, `labnosh-protein-max-choco-400`, 그리고 그 파일에 있는 파우더·두유 예시가 있으면 읽고 같은 문체·밀도로 쓴다. 사람 편집자가 제품을 보고 고르는 사람에게 핵심만 짚어 주는 글이다.

## 수치 근거
- 제품 데이터: `app/data/{drink,bar,shake,yogurt,soymilk,powder}ProductsData.json`. `app/data/productOverrideLocal.json`에 같은 slug 값이 있으면 그 값이 우선.
- 계산이 필요한 비교(순위, "이보다 많은 제품 N개", 차이)는 반드시 Python 스크립트로 데이터를 읽어 계산한다. 머리로 세지 않는다. 계산한 방법은 sources에 "계산: ..."으로 적는다.
- 참고: `.tmp-editorial-1108-v2.json`(스크립트가 만든 초안)의 순위 숫자는 재검산을 통과했다. 계산 결과를 확인하는 데 써도 되지만 문장은 베끼지 않는다.
- 성분표 이미지(`app/data/slugTo*Spec.json` → `public/*-spec/`)는 데이터에 없는 값이 필요할 때만 열어 본다. 읽은 값은 sources에 파일명과 값을 적는다. 확실히 못 읽으면 쓰지 않는다.

## 카테고리 규칙
- 파우더: 데이터의 1회 제공량(servingSizeG) 기준. 파우더끼리만 비교(지금 69종). 1회 제공량이 100g 이상인 게이너류는 "한 스쿱"이라 하지 말고 "1회 제공량 300g"처럼 쓰고, 게이너(열량 보충용)라는 성격을 데이터 수치로 설명한다. 당류가 null이면 당류를 말하지 않는다. 단백질 원료(proteinSource)는 데이터에 있을 때만 쓴다. 통 전체 단백질 같은 새 계산은 하지 않는다.
- 두유: 1팩 단백질 구간 — 고단백 11g 이상 / 단백질 강화 8~10g / 일반 5~7g.
- 바: 1개 단백질 5g 미만이면 watchOut에 '단백질 보조 간식'이라고 쓴다.
- 쉐이크·음료·요거트: 기존 예시와 같은 방식(1회분·1병·1개 기준).

## 금지
- 효능(근육 증가·다이어트 효과 등), 가격, 판매량, 인기, 맛 평가, 출처 없는 통계.
- 내용 없는 문장: "나란히 볼 수 있습니다", "함께 확인할 수 있습니다", "~도 따로 확인하세요", "수치를 기준으로 비교하려는 분", "~을 맞추려는 분", "열량을 Nkcal 안쪽으로 두고 싶은 분"처럼 숫자만 끼운 추천.
- 제품명 뒤 괄호 바로 다음 조사("(바닐라)은"). 은/는·이/가·을/를·와/과는 앞 글자 받침에 맞춘다.
- 같은 문장 틀을 제품마다 반복하지 않는다. 같은 라인 맛 차이 제품은 맛별 차이(제공량·열량·당류·나트륨)나 다른 비교로 글을 다르게 쓴다. 차이가 없으면 "맛만 다르고 수치는 같다"를 한 번만 말한다.

## 분량·형식
- summary 2문장: 제품이 무엇인지 + 가장 눈에 띄는 수치 사실(위치·비교 포함).
- points 3~4개: 각각 고르는 데 쓸 수 있는 비교 사실 하나. 최소 2개는 계산 비교(카테고리 안 위치, 가까운 대안과의 숫자 차이).
- goodFor 2개: 실제 상황(예: "운동 후 한 번에 단백질 30g 안팎을 채우되 당류는 피하고 싶은 분", "아침 대용으로 열량 있는 한 잔이 필요한 분").
- watchOut 1~2개: 이 제품의 약점이나 주의점을 수치로.
- compareSlugs 2~3개: 같은 카테고리, 실제 존재하는 slug.
- 존댓말, 짧은 문장.

## 끝나고
OUT 파일을 저장한 뒤 `python -X utf8 -c "import json;d=json.load(open('<OUT>',encoding='utf-8'));print(len(d))"`로 개수를 확인한다. 보고는 짧게: 쓴 개수, 못 쓴 slug와 이유, 성분표에서 읽은 값 목록.

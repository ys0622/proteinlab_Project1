# ProteinLab Mobile-first Redesign PRD

## 1. 배경

ProteinLab은 아직 트래픽 규모가 크지는 않지만 월 방문자가 100명을 넘기기 시작한 상태다. 이 단계의 방문자는 검색 유입과 초기 신뢰 형성에 중요한 자산이므로, 개편 과정에서 기능 오류, 한글 깨짐, 쿠팡 링크 누락, 모바일 사용성 저하가 발생하면 안 된다.

CareMap은 모바일 사용을 전제로 홈 화면에서 상황 선택, 조회 많은 제품, 구매 CTA, 가이드 콘텐츠가 빠르게 이어지도록 설계되어 있다. ProteinLab도 모바일 접속 비중이 높으므로 홈 화면부터 모바일 탐색과 구매 전환에 맞게 재설계한다.

## 2. 목표

1. 모바일 사용자가 첫 화면에서 원하는 제품군과 선택 목적을 빠르게 고를 수 있게 한다.
2. 홈 화면을 제품 탐색과 구매처 클릭으로 이어지는 모바일 허브로 만든다.
3. 제품 카드에서 핵심 정보와 쿠팡 CTA를 더 명확하게 보여준다.
4. 기존 방문자의 이탈을 막기 위해 기존 주요 URL, 쿠팡 링크, 제품 상세, 카테고리 기능을 유지한다.
5. 국제미각상, 저당, 고단백, 신규/화제 제품 같은 신뢰 신호를 수익화에 도움이 되는 위치에 노출한다.
6. 개편은 빠르게 진행하되, 배포 전 회귀 검수 기준을 엄격하게 둔다.

## 3. 비목표

- 전체 사이트를 한 번에 전면 재설계하지 않는다.
- 카테고리, 랭킹, 추천, 제품 상세 전체 UI를 동시에 갈아엎지 않는다.
- 기존 ProductCard를 전체 사이트에서 즉시 교체하지 않는다.
- 쿠팡 파트너스 링크 구조를 다시 바꾸지 않는다.
- GA4 이벤트 체계를 대규모로 다시 설계하지 않는다.
- 검색 URL, canonical, sitemap 구조를 불필요하게 변경하지 않는다.

## 4. 핵심 사용자

### 모바일 검색 유입 사용자

- 검색으로 ProteinLab에 처음 들어온 사용자
- 제품명, 단백질 음료 추천, 저당, 고단백, 다이어트, 뉴케어 올프로틴 같은 의도를 가진 사용자
- 긴 설명보다 빠른 후보 확인과 구매처 이동을 원하는 사용자

### 비교 탐색 사용자

- 단백질 함량, 당류, 칼로리 기준으로 제품을 좁히고 싶은 사용자
- 제품 상세와 비교 페이지를 오가며 최종 구매 후보를 고르는 사용자

### 구매 직전 사용자

- 이미 제품군을 어느 정도 알고 있고 쿠팡 구매처를 바로 확인하려는 사용자
- 맛, 수상 이력, 저당, 고단백 같은 보조 신뢰 신호에 반응할 가능성이 있는 사용자

## 5. 핵심 원칙

1. 모바일 우선
   - 모바일 360px~430px 화면을 기준으로 먼저 설계한다.
   - 데스크톱은 모바일 구조가 자연스럽게 확장되는 형태로 처리한다.

2. 빠른 판단
   - 홈 첫 2스크린 안에서 제품군, 목적, 제품 후보, 쿠팡 CTA가 보여야 한다.

3. 구매 CTA 명확화
   - 홈 제품 카드에서는 쿠팡 CTA를 명확하게 보여준다.
   - 카드 클릭은 상세 이동, 버튼 클릭은 쿠팡 이동으로 역할을 분리한다.

4. 기존 자산 보호
   - 기존 검색 유입 URL과 쿠팡 링크는 보존한다.
   - 기존 카테고리/상세/비교 기능이 깨지지 않아야 한다.

5. 점진 적용
   - 홈 화면과 홈 전용 카드부터 적용한다.
   - 검수 후 카테고리, 제품 상세, 비교 화면으로 확장한다.

## 8. 카테고리 전환 방식

홈 상단 카테고리 스위처를 누르면 같은 홈 화면 안에서 제품 섹션이 해당 카테고리 기준으로 바뀐다.

예시:

| 선택 카테고리 | 제품 섹션 |
|---|---|
| 음료 | 많이 보는 음료, 맛 수상/화제 음료, 저당 음료, 고단백 음료, 입문용 음료 |
| 쉐이크 | 많이 보는 쉐이크, 식사대용 쉐이크, 저당 쉐이크, 운동 후 쉐이크, 입문용 쉐이크 |
| 바 | 많이 보는 바, 저당 바, 간식 대체 바, 고단백 바, 입문용 바 |
| 요거트 | 많이 보는 요거트, 저당 요거트, 고단백 그릭요거트, 마시는 요거트, 입문용 요거트 |

각 섹션의 전체보기는 실제 카테고리 페이지로 이동한다.

## 9. 홈 전용 제품 카드 요구사항

### 목적

홈 카드의 목적은 상세한 비교가 아니라 빠른 판단과 구매처 클릭이다.

### 필수 표시 정보

- 제품 이미지
- 브랜드
- 제품명
- 단백질
- 당류
- 칼로리
- 용량
- 핵심 배지 1~2개
- 쿠팡 CTA

### 배지 후보

- 국제미각상
- 저당
- 고단백
- 락토프리
- 신규
- 화제

### 제외 요소

- 찜 버튼
- 공유 버튼
- 비교 버튼
- 네이버/공식몰 다중 버튼
- 과도한 등급 배지
- 상세 성분 4분할 박스
- 긴 제품 설명

### 카드 UX

- 카드 클릭: 제품 상세 이동
- 쿠팡 버튼 클릭: 쿠팡 링크 이동
- 버튼 높이: 최소 44px
- 제품명: 최대 2줄
- 카드 폭: 모바일 기준 약 170~190px
- 한 화면에 카드 1.4~1.7개가 보이도록 조정
- 이미지 영역 높이 고정
- 배지와 이미지/버튼이 겹치지 않아야 함

## 10. 제품 노출 로직

### 기본 원칙

- 기존 조회수 + 스펙 기반 hybridScore를 유지한다.
- 단, 홈에서는 목적별 섹션에 맞는 선별 로직을 추가한다.
- 판매량처럼 확인되지 않은 표현은 쓰지 않는다.

### 섹션별 로직

| 섹션 | 기준 |
|---|---|
| 지금 많이 보는 제품 | hybridScore |
| 맛 수상/화제 제품 | awards 필드 또는 운영자 지정 |
| 저당 제품 | 당류 기준 |
| 고단백 제품 | 카테고리별 단백질 기준 |
| 처음 시작하기 좋은 제품 | 중간 단백질, 낮은 당류, 구매 링크 있음, 과도한 초고단백 제외 |

### 임시 운영자 지정

신규 수상, 캠페인, 계절성 제품은 임시 운영자 지정 목록으로 홈 노출을 보강할 수 있다.

필수 조건:

- 임시 지정 목록은 코드에서 명확히 이름을 붙인다.
- 수동 지정 이유를 주석 또는 문서로 남긴다.
- 특정 기간 후 제거 또는 재검토할 수 있어야 한다.

## 11. 수익화 요구사항

1. 홈 전용 제품 카드에는 쿠팡 CTA를 명확히 노출한다.
2. 쿠팡 링크가 없는 제품은 CTA를 숨기거나 비활성화한다.
3. 쿠팡 링크가 없는 제품이 홈 전략 섹션 상위에 노출되지 않도록 한다.
4. 쿠팡 CTA 문구는 과장하지 않는다.
5. 제휴 고지는 홈 제품 섹션 근처 또는 하단에 유지한다.
6. 제품 순위와 제휴 수익은 분리해서 설명한다.

권장 CTA 문구:

- 쿠팡 최저가 확인하기
- 쿠팡 구매처 확인
- 쿠팡에서 보기

금지 표현:

- 판매량 1위
- 무조건 추천
- 최저가 보장
- 효과 보장

## 12. 측정 요구사항

기존 이벤트 체계를 크게 바꾸지 않고, 최소한 다음 구분이 가능해야 한다.

| 행동 | 이벤트 |
|---|---|
| 홈 카테고리 선택 | home_category_click 또는 filter_apply |
| 목적 칩 선택 | home_goal_click 또는 filter_apply |
| 홈 제품 카드 클릭 | product_card_click |
| 홈 쿠팡 CTA 클릭 | affiliate_click 또는 기존 purchaseClick |
| 가이드 CTA 클릭 | internal_cta_click |

필수 파라미터:

- product_id
- product_name
- product_category
- link_position=home_featured
- retailer=coupang
- page_path

## 13. SEO 요구사항

- 홈 canonical 유지
- 기존 주요 가이드 URL 유지
- sitemap 불필요 변경 금지
- 제품명/수상 정보는 사실 기반으로만 작성
- 국제미각상은 맛 평가 참고 정보로만 설명
- 의료적 효능 또는 영양 효과로 해석하지 않음

## 14. 접근성 요구사항

- 카테고리 스위처는 버튼 역할을 명확히 한다.
- 선택 상태를 시각적으로 구분한다.
- 쿠팡 CTA는 키보드 접근 가능해야 한다.
- 카드 클릭 영역과 CTA 클릭 영역이 충돌하지 않아야 한다.
- 버튼 터치 영역은 44px 이상이어야 한다.
- 이미지 alt는 브랜드 + 제품명 기준으로 제공한다.

## 15. 성능 요구사항

- 홈 첫 화면 LCP 이미지가 과도하게 커지지 않아야 한다.
- 제품 카드 이미지는 고정 크기 컨테이너에서 object-contain 처리한다.
- 캐러셀은 CSS overflow 기반을 우선 사용한다.
- 불필요한 대형 JS 라이브러리 추가 금지
- 모바일에서 CLS가 발생하지 않도록 카드 높이를 안정화한다.

## 18. 롤백 계획

1. 홈 전용 카드와 홈 구조 변경은 독립 커밋으로 관리한다.
2. 문제가 발생하면 홈 화면만 이전 커밋으로 되돌릴 수 있어야 한다.
3. 기존 `ProductCard`를 전역 교체하지 않기 때문에 카테고리/상세/랭킹 영향은 최소화한다.
4. 배포 직후 모바일 홈에서 쿠팡 CTA 또는 카드 클릭 문제가 있으면 즉시 롤백한다.

## 19. 성공 지표

### 단기

- 모바일 홈 이탈률 감소
- 홈 제품 카드 클릭 증가
- 홈 쿠팡 CTA 클릭 증가
- 제품 상세 진입 증가

### 28일

- 사용자당 조회수 증가
- 홈 → 제품 상세 클릭률 증가
- 홈 → 쿠팡 클릭률 증가
- 뉴케어 올프로틴 관련 페이지 노출/클릭 증가

### 수익화

- 쿠팡 파트너스 클릭 증가
- 전략 제품 클릭 증가
- 구매 의도 높은 페이지로 이동 증가

## 20. 출시 전 최종 판단 기준

다음 중 하나라도 실패하면 배포하지 않는다.

- 홈 모바일에서 제품 카드 CTA가 보이지 않음
- 쿠팡 링크가 누락되거나 상세보기로 바뀜
- 한글 깨짐이 새로 발생함
- 제품 상세 이동이 깨짐
- 카테고리 이동이 깨짐
- 빌드 실패
- 모바일에서 카드/텍스트가 겹침
- 제휴 고지가 사라짐

## 21. 권장 첫 구현 범위

첫 구현은 아래 범위로 제한한다.

1. 홈 전용 제품 카드
2. 홈 카테고리 스위처
3. 홈 목적별 제품 섹션
4. 음료 카테고리의 맛 수상/화제 제품 노출
5. 기존 홈 가이드/콘텐츠 일부 재배치

이 범위만으로도 모바일 첫 화면 전환력과 수익화 CTA 노출은 크게 개선할 수 있다. 카테고리, 상세, 비교 화면의 모바일 개편은 홈 배포 후 지표와 오류 여부를 확인한 뒤 2차 작업으로 진행한다.

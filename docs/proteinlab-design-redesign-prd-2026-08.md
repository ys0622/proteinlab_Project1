# ProteinLab Design Redesign PRD

작성일: 2026-08-03  
대상 서비스: proteinlab.kr  
문서 목적: 실제 구현 전에 ProteinLab의 현 구조, 데이터, 수익화 흐름, SEO 자산을 보존하면서 모바일 중심 디자인 개선 범위를 명확히 정의한다.

---

## 1. 배경

ProteinLab은 단백질 제품 데이터베이스, 비교, 추천, 가이드 콘텐츠, 쿠팡파트너스 구매 링크를 함께 운영하는 단백질 제품 탐색 서비스다.

현재 서비스는 검색 유입과 제품 데이터 자산을 갖추고 있지만, 화면 경험은 다음 문제가 있다.

- 모바일 접속 비중이 높은 서비스인데도 화면 밀도와 CTA 구조가 모바일 커머스 경험에 충분히 맞춰져 있지 않다.
- 제품 카드가 많은 정보를 담으면서 카드 높이, 버튼 위치, 배지 수가 흔들릴 위험이 있다.
- “제품 상세 보기”와 “구매처 확인”의 역할이 화면마다 혼재될 수 있다.
- 일부 소스 파일에 한글 깨짐이 남아 있어 디자인 개선 과정에서 문구 품질과 SEO 메타가 훼손될 위험이 있다.
- 메인, 카테고리, 제품 상세, 트렌딩 페이지가 각각의 역할을 충분히 다르게 수행하지 못한다.

이번 개편은 단순히 예쁜 화면을 만드는 작업이 아니라, **모바일 사용자가 더 빠르게 제품을 고르고 쿠팡 구매처로 이동하게 만드는 전환 중심 UX 개선**이다.

---

## 2. 프로젝트 목표

### 2.1 핵심 목표

1. 모바일 사용자가 첫 화면에서 제품 탐색 방향을 바로 이해한다.
2. 제품 카드에서 핵심 수치와 구매 CTA를 명확하게 구분한다.
3. 제품 상세 페이지를 구매 전 최종 판단 화면으로 강화한다.
4. 트렌딩 페이지를 검색 유입과 제품 상세/구매 클릭을 연결하는 허브로 만든다.
5. 기존 SEO URL, 제품 데이터, 쿠팡파트너스 링크, GA4 측정 흐름을 훼손하지 않는다.
6. 디자인 개선 과정에서 카드 높이 흔들림, 한글 깨짐, 기능 회귀를 방지한다.

### 2.2 비즈니스 목표

- 제품 상세 진입률 증가
- 쿠팡 구매처 클릭률 증가
- 모바일 이탈률 감소
- 검색 유입 콘텐츠에서 제품/비교 페이지로의 이동 증가
- 신규/전략 제품 노출 품질 개선

---

## 3. 범위

### 3.1 1차 개편 대상

이번 PRD 기준 1차 구현 대상은 다음 4개 페이지다.

| 페이지 | URL | 핵심 역할 |
|---|---|---|
| 메인 | `/` | 모바일 첫 진입, 추천 제품, 카테고리 진입, 인기/전략 제품 노출 |
| 제품 리스트 | `/drinks` | 단백질 음료 탐색, 필터, 정렬, 제품 카드, 구매 CTA |
| 제품 상세 | `/product/labnosh-protein-max-strawberry-400` 외 전체 상세 템플릿 | 구매 전 최종 판단, 영양 분석, 구매처 클릭 |
| 트렌딩 | `/trending` | 현재 관심 제품/주제 허브, 제품 상세 및 가이드 연결 |

### 3.2 1차 제외 범위

- 전체 사이트 리브랜딩
- 제품 데이터 구조 대규모 변경
- 쿠팡파트너스 링크 생성 또는 교체
- GA4 이벤트 체계 전면 재설계
- 추천 알고리즘 전면 개편
- 비교 기능 전면 개편
- 관리자 페이지 디자인 개편
- 모든 가이드 콘텐츠 템플릿 일괄 변경

## 5. 디자인 원칙

### 5.1 모바일 우선

- 기본 설계 기준은 360px~430px 모바일 화면이다.
- PC는 모바일 구조를 억지로 늘리는 방식이 아니라, 같은 정보 우선순위를 넓은 그리드로 확장한다.
- 모바일 첫 화면에서 사용자가 최소한 다음을 이해해야 한다.
  - 어떤 서비스인지
  - 어떤 제품군을 볼 수 있는지
  - 지금 바로 볼 만한 제품은 무엇인지
  - 구매처 확인 버튼이 어디 있는지

### 5.2 제품 중심

- 제품 이미지는 카드와 상세 화면의 첫 번째 시각 신호가 되어야 한다.
- 장식용 배경보다 실제 제품 이미지, 영양 수치, CTA를 우선한다.
- 단, 제품 이미지를 무리하게 합성하거나 실제와 다른 패키지처럼 보이게 만들지 않는다.

### 5.3 카드 안정성

제품카드는 크기와 정보량이 흔들리면 안 된다.

필수 규칙:

- 카드 이미지 영역 높이 고정
- 제품명 최대 2줄
- 배지 최대 2~3개
- CTA 영역 높이 고정
- 카드 전체 높이 variant별 고정 또는 최소/최대 범위 지정
- `new` 같은 보조 배지는 카드 크기를 흔들면 제거
- 쿠팡 구매 버튼은 기존처럼 명확하게 노출

### 5.4 CTA 역할 분리

- 카드 본문 클릭: 제품 상세 이동
- 쿠팡 버튼 클릭: 쿠팡 구매처 이동
- 비교 버튼 클릭: 비교함 추가
- 즐겨찾기 버튼 클릭: 즐겨찾기

같은 클릭에서 상세 이동과 구매 클릭이 동시에 발생하면 안 된다.

### 5.5 수익화 우선순위

- 쿠팡 링크가 있는 제품은 구매 CTA를 명확히 보여준다.
- 쿠팡 링크가 없는 제품은 CTA를 숨기거나 “구매처 준비 중” 등으로 안전하게 처리한다.
- 쿠팡 링크가 없는 제품을 메인 구매 중심 섹션 최상위에 과도하게 노출하지 않는다.
- “최저가 보장”, “판매 1위”처럼 검증 불가능한 표현은 사용하지 않는다.

## 6. 레퍼런스 해석

사용자가 제공한 레퍼런스의 핵심은 다음이다.

### 6.1 모바일 메인 레퍼런스

핵심 요소:

- 상단 딥그린 헤더
- 큼직한 브랜드 로고
- 검색/장바구니/메뉴 아이콘
- 제품 중심 대형 히어로 캐러셀
- 상품 카드형 세로 리스트
- 하단 고정 네비게이션
- 카드 내부 구매 버튼이 명확함

ProteinLab 적용 방향:

- 장바구니 대신 “비교함” 또는 “즐겨찾기” 개념으로 변환
- 가격이 최신 데이터가 아니면 가격 표시보다 “쿠팡 구매처 확인” 사용
- 메인 히어로는 `추천 제품`, `초고함량`, `저당`, `뉴케어 올프로틴` 같은 전략 섹션으로 구성

### 6.2 모바일 상세 레퍼런스

핵심 요소:

- 제품 이미지가 화면 상단 대부분을 차지
- 하단으로 자연스럽게 제품명/핵심 수치/분석이 이어짐
- 단백질, 칼로리, 당류 3대 지표를 큼직하게 노출
- 하단 고정 구매 CTA

ProteinLab 적용 방향:

- 제품 상세 상단을 이미지 중심으로 재편
- 첫 화면에 단백질, 칼로리, 당류, 용량, 등급, 구매 CTA 배치
- 분석은 “상세 분석” 아래로 두되, 구매 결정에 필요한 요약을 먼저 제공

### 6.3 PC 레퍼런스

핵심 요소:

- 딥그린 헤더
- 넓은 제품 이미지 영역
- 데이터 카드와 CTA가 우측에 정렬
- 제품 리스트는 4열 카드형
- 도넛 차트/성분 비율 등 데이터 시각화

ProteinLab 적용 방향:

- PC 제품 상세는 좌측 제품 이미지, 우측 분석/CTA 구조 유지
- `/drinks`는 4열 고정 카드와 상단 필터/정렬을 유지
- 도넛 차트는 1차에서는 선택 사항. 구현 비용 대비 효과가 낮으면 막대/배지 기반으로 시작

## 7. 정보 구조

### 7.1 메인 페이지 `/`

목적:

- 처음 온 사용자가 제품군을 빠르게 선택한다.
- 전략 제품과 구매 가능 제품을 노출한다.
- 제품 상세/리스트/추천/트렌딩으로 분기한다.

모바일 화면 순서:

1. 상단 헤더
   - 로고
   - 검색
   - 비교함 또는 즐겨찾기
   - 메뉴

2. 메인 히어로
   - 제목: “내게 맞는 단백질 제품 찾기”
   - 짧은 설명: “369개 제품을 단백질, 당류, 칼로리 기준으로 비교”
   - CTA: “음료부터 보기”, “맞춤 추천”

3. 전략 제품 캐러셀
   - 쿠팡 링크가 있는 제품 우선
   - 예시 후보:
     - 랩노쉬 프로틴 드링크 맥스 딸기: 52g, 230kcal, 당류 0g, 쿠팡 있음
     - 뉴케어 올프로틴 초콜릿: 25g, 135kcal, 당류 0g, 쿠팡 있음
     - 뉴케어 올프로틴 41g 커피우유: 41g, 210kcal, 쿠팡 있음
     - 테이크핏 익스트림: 60g, 259kcal, 쿠팡 있음

4. 카테고리 전환
   - 음료
   - 바
   - 요거트
   - 쉐이크

5. 목적별 칩
   - 저당
   - 고단백
   - 초고함량
   - 식사대용
   - 운동 후
   - 시니어/균형영양

6. 제품 섹션
   - 지금 많이 보는 제품
   - 고단백 제품
   - 저당 제품
   - 신규 등록 제품
   - 뉴케어 올프로틴/국제 미각상 관련 전략 콘텐츠 연결

7. 콘텐츠 섹션
   - 단백질 음료 TOP10
   - 고단백 40g 이상 비교
   - 저당 단백질 음료
   - 뉴케어 올프로틴 가이드

PC 화면:

- 헤더 + 넓은 히어로
- 히어로 아래 추천 제품 가로 캐러셀
- 4열 제품 섹션
- 콘텐츠 카드 3열

성공 기준:

- 모바일 첫 화면에서 제품 CTA 1개 이상 노출
- 쿠팡 링크가 있는 제품의 구매 CTA가 명확함
- 카드 높이 흔들림 없음
- `/drinks`, `/recommend`, `/trending`, 제품 상세로 자연스럽게 이동

### 7.2 제품 리스트 페이지 `/drinks`

목적:

- 단백질 음료 124개를 조건에 따라 좁힌다.
- 제품 상세와 쿠팡 구매처로 빠르게 이동한다.

모바일 화면 순서:

1. 헤더
2. 카테고리 요약
   - “단백질 음료 124개”
   - 핵심 설명 1줄
3. 빠른 필터 칩
   - 저당 3g 이하
   - 고단백 20g 이상
   - 저칼로리 150kcal 이하
   - 초고함량 40g 이상
   - 쿠팡 구매 가능
4. 정렬
   - 추천순
   - 단백질 높은순
   - 당류 낮은순
   - 칼로리 낮은순
   - 최근 등록순
5. 제품 카드 리스트
6. 하단 비교함 바

제품카드 필수 정보:

- 제품 이미지
- 브랜드
- 제품명
- 용량
- 단백질
- 칼로리
- 당류
- 핵심 배지 최대 2개
- 쿠팡 구매처 버튼
- 비교 추가 버튼

제품카드 금지:

- 불필요한 `new` 배지로 카드 높이를 늘리는 것
- 정보 배지 4개 이상 노출
- 구매 버튼이 접히거나 보이지 않는 것
- 제품명이 3줄 이상으로 늘어나는 것

PC 화면:

- 좌측 필터 사이드바 + 우측 제품 그리드 구조
- 필터 사이드바는 PC에서 좌측 고정 컬럼으로 노출
- 우측 상단에는 카테고리명, 제품 수, 정렬 드롭다운 배치
- 우측 본문은 4열 제품 그리드
- 카드 높이 통일
- 구매 CTA와 비교 CTA 위치 고정

PC 레이아웃 세부 요구사항:

- 전체 컨테이너는 화면 폭을 넓게 활용하되 최대 폭을 관리한다.
- 좌측 필터 폭은 260~300px 수준으로 고정한다.
- 우측 제품 영역은 남은 공간을 사용한다.
- PC 기준 레이아웃 예시:
  - 좌측: `Filters`, `Clear all`, 필터 그룹
  - 우측: `Protein Drinks`, `124 products`, `Sort by`
  - 상품: 4열 카드
- 필터 그룹 예시:
  - 단백질 기준: 20g 이상, 40g 이상, 50g 이상
  - 당류 기준: 0g, 3g 이하, 5g 이하
  - 칼로리 기준: 150kcal 이하, 200kcal 이하
  - 등급 기준: 밀도 A, 다이어트 A/B, 퍼포먼스 A
  - 구매 가능: 쿠팡 링크 있음
  - 브랜드: 랩노쉬, 뉴케어, 더단백, 닥터유, 테이크핏 등
- 필터 항목에는 결과 수를 표시한다.
- 체크박스는 최소 20px 이상, 라벨 클릭 가능 영역은 44px에 가깝게 확보한다.
- 긴 필터 그룹은 접기/펼치기를 지원한다.
- 좌측 필터는 PC에서만 항상 보이고, 모바일에서는 바텀시트 또는 상단 필터 버튼으로 전환한다.
- 좌측 필터가 생겨도 모바일 구조와 URL query 동작은 동일해야 한다.
- 정렬 드롭다운은 우측 상단에 유지한다.
- 카드 내부 수치 영역은 레퍼런스처럼 단백질/칼로리/당류 3개 핵심 지표를 우선한다.
- 도넛 차트는 PC 리스트 1차 필수는 아니며, 카드 높이와 렌더링 성능을 해치지 않을 때만 적용한다.

성공 기준:

- 필터 적용 후 URL query 유지
- 뒤로가기/새로고침 정상
- 카드 높이 동일
- 쿠팡 링크 있는 제품의 구매 CTA 유지
- 쿠팡 링크 없는 제품에서 오류 없음
- PC에서 좌측 필터와 우측 그리드가 겹치지 않음
- PC 1440px 이상에서 4열 카드가 안정적으로 유지됨
- 1024~1280px에서는 필터 폭과 카드 열 수가 자연스럽게 조정됨

### 7.3 제품 상세 페이지 `/product/[slug]`

목적:

- 사용자가 구매 전 최종 판단을 한다.
- 제품 스펙, 상대 평가, 구매처를 한 화면 흐름 안에서 확인한다.

대표 기준 제품:

- URL: `/product/labnosh-protein-max-strawberry-400`
- 브랜드: 랩노쉬
- 제품명: 프로틴 드링크 맥스 (딸기)
- 용량: 400mL
- 단백질: 52g
- 칼로리: 230kcal
- 당류: 0g
- 단백질 밀도: 13.0g/100ml
- 등급: 단백질 밀도 A, 다이어트 A, 퍼포먼스 A
- 쿠팡 링크: 있음
- 공식몰 링크: 있음

모바일 화면 순서:

1. 상단 내비
   - 뒤로가기
   - ProteinLab
   - 공유

2. 제품 이미지 히어로
   - 실제 제품 이미지 중심
   - 이미지 영역 높이 고정
   - 이미지 없는 제품 fallback 필요

3. 제품 기본 정보
   - 브랜드
   - 제품명
   - 한 줄 요약
   - 즐겨찾기

4. 핵심 수치 카드
   - 단백질
   - 칼로리
   - 당류
   - 용량

5. 상세 분석
   - 단백질 밀도
   - 다이어트 지표
   - 퍼포먼스 지표
   - 동일 카테고리 내 비교 기준 표시

6. 구매 CTA
   - 상단 또는 하단 중 1개는 반드시 첫 화면 근처
   - 모바일 하단 sticky CTA 적용
   - 쿠팡 링크 있으면 “쿠팡 구매처 확인”
   - 공식몰 있으면 보조 CTA

7. 관련 제품
   - 같은 카테고리
   - 더 낮은 당류
   - 더 높은 단백질
   - 비슷한 용량
   - 구매 가능

PC 화면:

- 좌측: 제품 이미지 갤러리
- 우측: 제품명, 등급, 핵심 수치, 구매 CTA
- 하단: 상세 분석, 영양성분, 관련 제품, FAQ

성공 기준:

- 모바일 첫 화면에서 제품명/핵심 수치/구매 CTA 접근 가능
- 제품 이미지가 과하게 잘리거나 작아지지 않음
- 구매 버튼 클릭과 제품 상세 이벤트가 섞이지 않음
- Product/Breadcrumb 구조화 데이터 유지
- 쿠팡 버튼이 사라지지 않음

### 7.4 트렌딩 페이지 `/trending`

목적:

- “지금 많이 보는 제품”을 보여준다.
- 검색 유입이 높은 주제를 제품 상세와 비교 콘텐츠로 연결한다.
- 단순 랭킹 페이지가 아니라 제품 탐색 허브가 된다.

현재 구조:

- `app/trending/page.tsx`
- 전체 카테고리 제품을 가져온 뒤 `hybridScore`와 `/api/popular` 조회수를 사용
- 카테고리별 상위 제품을 `ProductCard`로 렌더링

개선 방향:

1. 트렌딩 히어로
   - “지금 관심이 올라간 단백질 제품”
   - 기준 설명: 조회수 + 제품 스펙 기반 점수
   - 판매량 표현 금지

2. 카테고리별 트렌딩
   - 음료
   - 바
   - 요거트
   - 쉐이크

3. 전략 주제 카드
   - 초고함량 RTD
   - 저당 단백질 음료
   - 뉴케어 올프로틴
   - 국제 미각상/맛 수상 제품
   - 쿠팡 구매 가능 제품

4. 제품 상세 연결
   - 제품 카드 클릭: 상세
   - 구매 버튼 클릭: 쿠팡
   - 주제 카드 클릭: 가이드/토픽

성공 기준:

- 판매량처럼 오해될 표현 없음
- 제품 상세 이동과 구매 CTA 구분
- 트렌딩 기준 설명 표시
- 모바일에서 카테고리 전환이 쉬움

### 9.3 뉴케어 올프로틴 전략

사용자 피드백상 뉴케어 올프로틴은 콘텐츠 비중을 높일 가치가 있다.

적용 방향:

- 메인 전략 섹션에 뉴케어 올프로틴 25g/41g 라인 노출
- 트렌딩 주제 카드에 “뉴케어 올프로틴” 연결
- 상세/가이드에서는 국제 미각상 등 외부 수상 정보가 확인된 경우에만 표시
- 수상 정보는 맛 품질 평가로 설명하고, 건강 효능으로 해석하지 않는다.

주의:

- 내부 매출 정보는 공개 문구로 쓰지 않는다.
- “쿠팡 매출 2위” 같은 대외비성 표현은 화면/문서/코드에 넣지 않는다.

- Breadcrumb JSON-LD 유지
- 가격 데이터가 최신이 아니면 Offer schema를 무리하게 쓰지 않음
- 수상/인증 정보는 확인된 제품에만 표시

---

## 14. 접근성 요구사항

- 모든 버튼은 키보드 접근 가능
- 아이콘 버튼은 `aria-label` 제공
- 모바일 CTA 터치 영역 최소 44px
- 제품 이미지 alt는 브랜드+제품명
- 색상만으로 등급을 구분하지 않음
- 하단 sticky CTA가 콘텐츠를 가리지 않도록 spacer 제공

---

## 15. 성능 요구사항

- 제품 이미지는 Next Image 또는 기존 이미지 처리 방식 유지
- 첫 화면 주요 이미지는 priority 검토
- 리스트 이미지는 lazy loading
- 홈 `/api/popular` 호출은 빌드/ISR을 막지 않도록 timeout 또는 fallback 유지
- 제품 카드에서 불필요한 클라이언트 fetch 최소화
- 모바일에서 CLS 발생 금지

## 16. 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 한글 깨짐 | SEO/신뢰도 손상 | 디자인 전 주요 페이지 문구 인코딩 점검 |
| ProductCard 변경 폭 과대 | 전체 페이지 회귀 | 카드 안정화만 별도 커밋 |

# ProteinLab 개선 PRD (v3 — 단계별 로드맵)

## -1. 전체 작업 순서 (로드맵)

이번 개선은 홈만으로 끝나지 않는다. 아래 순서로 진행하되, **각 단계는 이전 단계 완료 후 실측 결과를 보고 다음 단계 범위를 재확정한다** — 지금 시점에 전체를 세부 스펙까지 확정하지 않는다.

| 단계 | 범위 | 상태 |
|---|---|---|
| **Phase 1. 홈** | `/` — 카테고리 아이콘, 인기 제품 카드의 영양정보 시각화(진행바) | 이번 PRD의 본문 (§0~§6) |
| **Phase 2. 리스트 페이지 + 제품 카드** | `/drinks` 등 리스트 페이지 필터 사이드바, `ProductCard.tsx`(전역 공용 카드)에 Phase 1 검증된 진행바 승격 적용 | 스켈레톤만 (§7) |
| **Phase 3. 그 외 콘텐츠** | 상세페이지 비교 막대그래프, 랭킹 페이지, `purchase-link` 접근성 정리 등 | 스켈레톤만 (§7) |

**중요한 설계 갈림길**: Phase 1의 "인기 제품 카드에 진행바 추가"는 사실 `ProductCard.tsx`(10개 페이지 공유 컴포넌트)를 건드리는 일이라 Phase 2 영역과 겹친다.

- **(A) 홈 전용 카드로 분리** — 홈에서만 쓰는 카드 컴포넌트에 진행바를 넣고, 전역 `ProductCard.tsx`는 Phase 2까지 그대로 둔다.
- **(B) `ProductCard.tsx`를 지금 바로 개선** — 전역 컴포넌트를 고쳐 모든 페이지에 즉시 반영한다.

**권장: (A).** 다른 9개 페이지(`/drinks`, `/compare`, `/trending` 등)에 실측 없이 밀어넣는 건 "작은 단위로, 검증하며" 원칙과 어긋난다. 홈 전용 카드로 먼저 검증 → Phase 2에서 전역 컴포넌트로 승격.

## 0. 이 문서가 존재하는 이유

이전에 로컬에서 6개 프롬프트로 진행한 홈 리뉴얼은 **실제 운영 중인 proteinlab.kr의 구조를 무시하고 처음부터 새로 만드는 방식**으로 진행되어, 오히려 아래 항목들을 훼손했다.

- Hero가 122px → 420px로 3배 이상 커짐 (여백 철학과 정반대)
- "단백질 밀도 A" 같은 라벨 붙은 등급 배지가 라벨 없는 원형 배지로 축소됨
- 카테고리 카드가 컬러풀한 그라데이션 타일에서 흰 배경 + 원형 제품사진으로 바뀌며 통일감이 떨어짐

**이 PRD는 실제 운영 사이트(proteinlab.kr)의 현재 구조·사이즈·정보 밀도·수익화 동선(쿠팡 CTA)을 베이스로 유지하면서, 레퍼런스에서 가져올 요소만 얹는 것을 목표로 한다.** 처음부터 다시 만들지 않는다.

> **정정**: 이전 버전 문서에서 "카드에 이미 진행바가 있다"고 적었던 부분은 **실측 결과 사실이 아니어서 정정**했다. 실제 라이브 카드의 DOM(`product-card__metrics`)을 직접 확인한 결과, 단백질/칼로리/당류/단백질밀도 4개 항목이 **테두리 박스 안에 라벨+숫자만** 있고 진행바나 게이지는 없다. 즉 레퍼런스(진행바·도넛차트) 대비 이 부분은 실제 갭이 맞고, Phase 1에 포함한다.

## 2. Phase 1 (홈) 작업 항목

### 2.1 카테고리 아이콘 통일성 (우선순위 1)
현재 이모지(🥤🍫🥛🧃) → **단색/라인 SVG 아이콘**으로 교체.
- 실사 제품사진 크롭 방식은 지난 시도에서 배경·색·비율이 제각각이라 통일감이 깨져 이미 실패했음 — 재시도하지 않는다.
- 음료 → 컵/보틀, 바 → 바(협형 스틱), 요거트 → 컵+스푼, 쉐이크 → 파우치/쉐이커
- 색상: 흰색 또는 반투명 화이트 (`rgba(255,255,255,0.92)`), 기존 그라데이션 타일과 충돌 없음
- 크기: PC 최대 32×32px, Mobile 최대 28×28px, stroke-width 1.8~2.2
- `aria-hidden="true"` 처리 — 접근성 이름은 기존 카테고리 텍스트가 담당
- 카드 크기/배경/그라데이션/링크/텍스트/제품수/간격/섹션 순서는 변경하지 않음. 카드 높이 증가 금지.
- 이미지 파일 asset보다 **컴포넌트 내부 SVG 상수 맵**(예: `CATEGORY_ICONS = { drink: <svg .../>, ... }`)으로 관리 — 카테고리가 4개뿐이라 별도 파일 관리가 오히려 번거로움

### 2.2 인기 제품 카드 — 영양정보 시각화 (우선순위 2, §-1의 (A) 방식)
- **홈 전용 카드 컴포넌트**를 새로 만들어(또는 지정해) 단백질/칼로리/당류 항목에 얇은 진행바를 추가
- 기준값(스케일)은 실제 데이터 분포 기반으로 설정 (예: 단백질 0~60g, 칼로리 0~400kcal, 당류 0~20g — 정확한 값은 실 데이터 분포 확인 후 확정)
- 등급 배지(라벨+A/B/C pill)는 그대로 유지, 진행바는 그 위에 "추가"되는 것이지 배지를 대체하지 않음
- 전역 `ProductCard.tsx`는 이번 단계에서 수정하지 않음 (Phase 2에서 검증 후 승격)

### 2.3 카드 등급 배지 여백 미세 조정 (우선순위 3, 선택)
- 구조(라벨+pill)는 그대로, pill 간 여백·폰트 크기만 실측 후 필요 시 미세 조정. 정보량 축소 금지.

## 3. Phase 1 수정 범위

**이번 작업은 홈(`/`)의 (1) 카테고리 카드 내부 아이콘 표현, (2) 인기 제품 카드의 영양정보 시각화 표현만 변경한다.**

카드의 크기, 배경색, 그라데이션, 링크, 텍스트, 제품 수, 간격, 섹션 순서, Hero, 쿠팡 CTA는 변경하지 않는다.

**수정 허용:**
- 홈 카테고리 카드 내부 아이콘 렌더링 (SVG 상수/작은 컴포넌트 추가 포함)
- 홈 전용 인기 제품 카드의 영양정보 표현 (박스+숫자 → 진행바 추가)

**수정 금지:**
- Hero 관련 클래스/높이/문구/검색창
- `HomePopularCarousel`(또는 동등 컴포넌트)의 섹션 구조·탭·순서 로직
- 전역 `ProductCard.tsx` (Phase 2 영역)
- 쿠팡 링크 컴포넌트 (`purchase-link` 계열) — 텍스트·동작·구조 전부
- 등급 배지 라벨/구조
- 제품 노출 순서 로직
- Header, Footer

## 4. 완료 기준

높이(px) 하나만으로는 폰트 렌더링·브라우저 차이로 오차가 생길 수 있으므로, **실제 뷰포트 노출 기준을 최종 판정 기준으로 삼는다.**

- [ ] PC 1440×900 기준: 첫 화면(스크롤 없이)에서 카테고리 4개 + 인기 제품 카드 최소 5개가 보이는가 (스크린샷으로 기록)
- [ ] Mobile 390×844 기준: 첫 화면에서 카테고리 카드 + 인기 제품 최소 2개가 보이는가 (스크린샷으로 기록)
- [ ] Hero 높이가 기존(약 122px) 대비 커지지 않았는가 (보조 지표)
- [ ] 등급 배지(라벨 포함)가 그대로 남아있는가
- [ ] 카테고리 카드의 색상 구분과 가로 배치가 유지되는가
- [ ] 진행바 추가로 카드 높이가 늘어나지 않았는가 (또는 늘어난다면 사전에 합의된 범위인가)
- [ ] 쿠팡 CTA가 정상 동작하는가 (`link.coupang.com` 또는 `/api/out/coupang` 내부 리다이렉트로 정상 연결)
- [ ] `HomePopularCarousel`, `purchase-link` 관련 파일에 의도치 않은 diff가 없는가 (§2.2 카드 분리 작업 외)
- [ ] 빌드 통과, 콘솔 에러 0건, 한글 깨짐 없음 (작업 전후 비교)

### 실패 조건 (아래 중 하나라도 해당하면 실패)
- 홈 인기 제품의 기본 노출 순서가 의도 없이 변경됨
- 현재 전략 제품(뉴케어 올프로틴, 닥터유, 오뚜기 등)의 노출이 밀림
- 쿠팡 CTA 텍스트가 "상세보기"로 바뀌거나 숨겨짐
- 등급 배지 유무 또는 진행바 추가로 인해 제품 카드 높이가 카드마다 들쭉날쭉해짐 (레이아웃 시프트)
- 모바일에서 카테고리 카드가 2줄 이상으로 밀려 첫 제품 노출이 늦어짐
- 전역 `ProductCard.tsx`에 의도치 않은 변경이 발생함

## 5. 참고: 확인된 별도 이슈 (이번 작업 범위 아님, Phase 3 후보)

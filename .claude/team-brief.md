# ProteinLab 팀 공통 브리핑

에이전트는 작업 전에 `CLAUDE.md`와 이 파일을 읽는다. 여기 적힌 내용은 이미 확인된 사실이므로 다시 조사하지 말고 새로운 발견만 보고한다. 갱신일: 2026-10-09.

## 에이전트 운영 구조
- 기본 구성은 메인 작업자(Claude) 1명과 3개 전문 에이전트다.
  - `proteinlab-data-auditor`: 제품·구매링크·이미지 데이터 정합성 감사. 기본은 보고만.
  - `proteinlab-release`: 타입체크 → 빌드 → 배포 → 라이브 회귀 검사 → push. 배포 요청 때만.
  - `proteinlab-seo-analyst`: GA4·서치콘솔·네이버 데이터 해석. 새 데이터가 있을 때만. 코드 수정 없음.
- 구현, 테스트, 커밋은 메인 작업자만 한다. 에이전트의 결과는 검토 없이 쓰지 않는다(근거 없는 수치 혼입 확인).
- 콘텐츠 작성 전담 에이전트는 두지 않는다. 필요해지면 추가한다.

## 호출 기준
- 일반 코드·콘텐츠 수정: 메인 작업자만
- 제품 등록·쿠팡 링크 반영·성분 수치 변경 후: `proteinlab-data-auditor`
- 배포: `proteinlab-release`(명시적 요청 시)
- 새 GA4/서치콘솔/네이버 데이터 또는 색인·유입 정체 분석: `proteinlab-seo-analyst`
- 동일 변경은 수정 완료 후 한 번만 재검수한다.

## 사이트
- proteinlab.kr — 단백질 음료·바·요거트·쉐이크 비교 (Next.js 16 App Router, Cloudflare Workers via OpenNext, Windows 배포). 상세는 `CLAUDE.md`.
- 수익: 쿠팡파트너스(케어맵과 계정 공용), 애드센스.
- 트래픽은 네이버가 대부분이고 구글 오가닉은 사실상 0(GA4 28일 기준 google/organic 5명).

## 이미 확인·해결한 것 (다시 찾지 말 것)
- 라이브 robots.txt·메타 정상. `/api/`, `/admin/` Disallow. 중복 비교 5쌍은 canonical 오버라이드 처리.
- `ProductCard` 실링크, 리스트 페이지 `force-dynamic`(정적 빌드가 빈 상품 목록을 내보내던 문제 수정).
- 제품 이미지 62개 WebP 변환, 주요 페이지 og:image 추가, 쿠팡 제휴 링크 `rel="sponsored"`.
- FAQ 스키마·콘텐츠 보강: market-insights, intake-strategy-health, 얇았던 요거트·바 가이드, `/compare`·`/recommend`.
- 구글 서치콘솔(9/21 기준): 수동 조치 없음, 색인 1개 / 미색인 약 800개(발견됨-미크롤링 581, 크롤링됨-미색인 162, NOINDEX 오래된 표시 51). 판단: 기술 버그가 아니라 도메인 신뢰도(백링크)와 시간 문제.
- 9/20 이후 반영된 큰 변경(확인 완료, 커밋 이력 기준): 골드박스 `/goldbox`와 갱신 워크플로우, 홈 인기·신제품·골드박스 발견 영역(`app/lib/homeDiscovery.ts`), 최근 실조회수 기반 순위(`recentPopularity.ts`), 가이드 허브 라우트·메타데이터, 랭킹 페이지네이션, 쉐이크 가이드·비교 랜딩 확장, MPI 가이드, GA4 KPI 관리자 화면과 구매링크 유형별 CTR 추적.
- GA4: 2026-10-03 12:12~10-04 12:29(KST) 약 24시간 분석 동의 기능이 수집을 막았다(동의 컴포넌트는 현재 미사용, GA4는 전체 방문자에게 로드).
- R2 ISR 캐시는 사용자가 계정 설정을 원하지 않아 보류(캐시 MISS와 느린 TTFB는 알려진 상태). 리스트 페이지는 서버 데이터 조회를 60초 메모리 캐시한다.

## 2026-10-09 이후 반영 (Claude 운영)
- 가이드 하단 구매 섹션: `GuideBuySection topic=...`(대표 제품은 `app/lib/guideBuyPicks.ts`). 요거트·바·쉐이크 브랜드 가이드 14개는 아직 제외.
- 구글 색인 진단: 서버·robots·canonical·렌더링 문제 없음(사이트맵 URL 전부 200). 크롤링 통계에서 새 URL 발견이 1% 미만. 원인은 도메인 신뢰도·콘텐츠 깊이로 추정(케어맵은 페이지당 본문이 3~4배 길고 URL 수가 절반 이하).
- `/topics` 허브와 하위 27개는 noindex이며 사이트맵에서 제외(얇은 랜딩).
- 데이터 기반 콘텐츠: 상품 페이지 "카테고리 내 위치"(`productPosition.ts`), 브랜드 "수치로 보는 …"(`brandProfile.ts`), 가이드 19개 `CategoryDataSection`. 요거트 250g·mL 초과 대용량은 1회 비교에서 제외(`servingScope.ts`).
- 공유 이미지(`app/opengraph-image.tsx`)의 가짜 예시 수치(25g/130kcal/0g)를 실제 제품 수로 교체. 한글 글리프 일부만 담은 내장 폰트라 새 한글 문구를 넣으면 깨질 수 있다.
- 남은 일: 본문이 얇은 기초·운동·브랜드 가이드 보강, 외부 링크 확보(사용자 작업), 색인 요청 리스트 20개(사용자), 크롤링됨-미색인 161개 목록 분석(사용자가 내보내기 파일 제공 시).
